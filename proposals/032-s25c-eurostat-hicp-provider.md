## Summary
The euro-area HICP series the deployment-gate data layer reads — ECB SDMX key `ICP.M.U2.N.000000.4.ANR` — is dead at source: its latest observation is `2025-12` and `startPeriod=2026-01` returns empty across all ICP reference areas (a 21st euro member joined in 2026 → ECB ICP `U2` migration lag). A same-signal, currently-updating channel exists on Eurostat's PEEI fast dataset `ei_cphi_m` (all-items HICP, annual rate, euro area), latest obs `2026-05 = 3.2%` on a 2026-06-18 live probe. This proposal adds a new `EurostatProvider` (JSON-stat), swaps the dead ECB key for the Eurostat series in `config/gates.yml`, and recalibrates the staleness thresholds to `amber=55 / red=90` (operator-confirmed; see §Risks and Risk Officer review) so the War Room reads a current inflation figure while the S-25 Bundle-A ungated-fold surfacing and cautious-fail behaviour stay intact.

## Motivation / Problem
- S-25 (Proposal 031) made stale ungated core-macro series drive `Data_Confidence_Tier`, and a live probe during that work surfaced the root cause: the ECB euro-area HICP key serves data only through `2025-12` (~169d stale against today). Banked as S-25c (PROGRESS.md:99).
- Steering live-investigation (2026-06-18, recorded in `local/brainstorms/2026-06.steering-s25c-hicp.md`): ECB SDMX has **no** current euro-area HICP channel (EA/EA21 area codes 404; ICP is THE HICP dataflow and all 35 reference areas top at `2025-12`). The detailed Eurostat `prc_hicp_manr` also lags. Only the fast PEEI channel `ei_cphi_m` is current.
- Same signal, not a substitute: all-items HICP YoY %, continuous with the ECB series (ECB last `2025-12`=1.9; Eurostat `2026-02`=1.9). No semantic drift — not a swap/expectation/nowcast.
- Consequence today: HICP perpetually contributes RED-by-staleness to `Data_Confidence_Tier`, an unflagged-for-6-months silent feed death that S-25's surfacing made visible but cannot fix without correcting the key.

## Proposal

### File-level manifest
1. **CREATE `scripts/data/providers/eurostat.py`** — `EurostatProvider(DataProvider)`, `source_name="EUROSTAT"`, `rate_limit=1.0`. A `_SERIES_REGISTRY` mapping alias → `(dataset, {indic,unit,geo} filter, units_label)`; `known_series()`; `fetch()` returning a `SeriesObservation`; a `_parse_jsonstat()` for the shape above. Reuses the shared `HttpClient` (no new HTTP code). Vintage = obs date (ECB L13 pattern — Eurostat's dataset-level `updated` timestamp is not a per-obs release date).
   **Parser selection rule (hardened per Challenger L5 — sparse JSON-stat):** JSON-stat omits null/suppressed observations from the `value` object. So the parser computes the highest ordinal `k` in `dimension.time.category.index`, then looks up `value[str(k)]`; if that key is **absent or null**, it raises `HttpError` (loud fail → `_fetch_all` aborts → never a silently-older value with a stale-but-fresh-looking vintage). It MUST NOT fall back to "highest key present in `value`" (which would silently return an older period). The non-null assertion is therefore a keyed lookup at the latest time-ordinal, not a max over present value-keys.

### Series-key / threshold detail
- gates.yml alias: `ei_cphi_m.TOTAL.RT12.EA` → registry maps to dataset `ei_cphi_m`, filter `{indic: TOTAL, unit: RT12, geo: EA}`, units label `pct_annual_rate` (matches the ECB ICP label for signal continuity).
- Vintage parse (Challenger L2 — scope the claim): the HICP series is **ungated**, so its `YYYY-MM` vintage flows through the **ungated fold path** (`gate_eval.py:458` → `_parse_vintage_to_date`), which already parses `YYYY-MM` (anchored first-of-month). No new vintage logic. (For completeness: the *gated* parse site at `gate_eval.py:391-396` wraps `date.fromisoformat` in `try/except (ValueError, KeyError)` → `None` → cautious, so even a hypothetical future gating of a `YYYY-MM` series degrades to cautious-AMBER rather than crashing — but HICP is not gated and this proposal does not gate it.)
- Thresholds `amber=55 / red=90`: euro-area HICP for month M publishes ~mid-M+1; with first-of-month vintage anchoring the latest-available print ages from ~47d (just published) to ~75d (just before the next refresh). 55/90 reads GREEN when genuinely fresh (≤55d), AMBER as the next print becomes due (~8wk mild caution), RED only on a genuinely stalled feed (max legitimate ~75d < 90 → RED never fires on legitimately-latest data). The threshold measures "did the pipeline MISS a publication," per gates.yml's own "calibrated to account for publication lags" comment.

## Risks & Mitigations
- **R1 — Risk-parameter relaxation (55/90 vs carried-forward 45/60).** `amber=55/red=90` is looser than the dead key's 45/60. Mitigation: operator-confirmed with rationale (measures a missed-publication, not the inherent monthly lag; 45/60 was never validated on a live series — the old key was always-RED, hiding the miscalibration). Risk Officer ratification mandatory (review-patterns.md "any code changes that alter risk parameters MUST be flagged for mandatory Risk Officer review").
- **R2 — Wrong guessed JSON-stat shape.** Mitigation: the cassette is captured from the **real** response, not hand-written; DoD #1 asserts the parse against it. JSON-stat ≠ ECB SDMX-JSON, so the parser is written fresh (only the class structure is copied from ecb.py).
- **R3 — Cautious-fail regression (silent GREEN on stale/None HICP).** Cardinal constraint. Mitigation: the source-agnostic ungated fold passes the literal `"live"` data_source; DoD #4 drives the fold path (not a cached fixture) and asserts None/unparseable → AMBER+.
- **R4 — SHA-cascade drift.** Mitigation: recompute against edited bytes; `TestArtefactSync` enforces REPLAY_DELTA.md + proposals/003; append-only discipline on history files.
- **R5 — Sandbox SSL block (self-signed proxy CA).** Mitigation (L6): capture the cassette via curl; run DoD #8 runtime-obs on the operator machine (needs `FRED_API_KEY` set); gate close-out on the live run — never fake or skip.
- **R6 — New data-source integration.** review-patterns.md: "any new data source integration MUST pass Data Standards review." Addressed via the CTO + Data-Standards lens in Core Team review and idempotent-fetch / rate-limit checks.
- **R7 — `amber_age_days` doubles as the fetch cache TTL (Challenger L3).** `_fetch_all` (`cli.py:90`) passes `amber_age_days` as the provider `max_age_days`, which the `HttpClient` uses as the on-disk cache freshness window. So `amber=55` lets a cached Eurostat body be served for up to 55 days on a non-`--no-cache` run. This is **pre-existing architecture for every series** (CPIAUCSL's `amber=45` is likewise its TTL), not introduced by 55/90, and it does **not** create silent-GREEN: a cached body carries its own real `vintage`, which the fold scores honestly (a stale cached body → stale vintage → correctly aged). Operators wanting the freshest read use `--no-cache`. Documented; no code change.
- **R8 — `_fetch_all` catches bare `Exception` (Challenger L8).** `cli.py:94` is `except (HttpError, Exception): sys.exit(1)`, so the `HttpError`-wrapping discipline in the parser buys no *differential* loop-level behaviour — any raise aborts. The `HttpError` wrap is retained for type-consistency with `ecb.py`'s parse path (semantic clarity), NOT because the loop distinguishes it. The cautious guarantee is the abort itself (loud, `sys.exit(1)`), not the exception type.
- **R9 — Signal continuity EA-vs-U2 (Challenger L11).** Eurostat is the **upstream primary publisher** of euro-area HICP; the ECB ICP dataflow re-disseminates Eurostat's figures, so `ei_cphi_m geo=EA indic=TOTAL unit=RT12` is the same published statistic the ECB key carried, not a proxy. A one-time YoY rebasing at the EA20→EA21 accession affects *any* euro-area HICP series identically and is immaterial to a staleness-and-level gate read. Resisted: a full overlapping-month back-comparison is out of scope for a staleness fix (the steering probe already cross-checked ECB `2025-12`=1.9 vs Eurostat `2026-02`=1.9 for order-of-magnitude continuity).
- **Blast radius:** MODERATE — provider plumbing imported by `cli.py`, `test_data_providers.py`, `test_live_smoke.py`. `test_live_smoke.py` carries no ICP *literal* but DOES have a source-routing coupling (`else ecb` fallthrough + `source in ("FRED","ECB")` assertion) that the new EUROSTAT source breaks — now in scope as manifest file 12 (Challenger L10). `_GATE_STALENESS` consistency test untouched (HICP is ungated; `SERIES_TO_GATE` carries no HICP mapping — verified).
