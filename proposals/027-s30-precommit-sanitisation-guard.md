# 027 — S-30 — Mechanical Pre-Commit Sanitisation Guard

**Tier: MEDIUM** — 5 files (4 CREATE + 1 MODIFY), established Python/tooling patterns, executable hook code, FULLY REVERSIBLE (no public push / external state in this session).

## Summary

A tracked Git pre-commit hook that cross-references the investor-private literals living in the gitignored `local/` ledger against the **staged tracked diff** and **blocks the commit** when a private literal would leak into a tracked file. The guard reads private literals directly from `local/` at runtime (never into any agent context), flags only the *intersection* of `(private literals) ∩ (staged additions)` filtered by a specificity floor, clears accepted-public identifiers through a parsed-canonical allowlist, and **no-ops gracefully** when `local/` is absent (a fresh cloner pre-onboarding is never blocked). Install is cloner-portable via `init_workspace.install_hook()` — every machine that runs the documented First-Run setup gets the guard with zero new dependency.

## Motivation / Problem

The sanitisation rule (no investor-private literals in tracked files) has been **noted-but-unenforced since Proposal 018** and has now recurred **N≥2**: the Proposal 026 test hardcoded the maintainer's real quantity / price / cost **and** the live NAV into a public tracked test file — caught by steering review, not by tooling. Manual review is demonstrably not a reliable gate (`MEMORY.md` 2026-06-04 governance entry: "fix = mechanical pre-commit gate (S-30), not another note"). PROGRESS.md row S-30 is the contract. The 2026-06-04 sanitisation audit note rules **accept-the-exposure** on already-public residuals (ISIN `IE000YYE6WK5`, `€5,100` cadence, backtesting session files) — **no history rewrite**; S-30 is **forward prevention only**.

**Ground truth established this session (not assumed):** `git log --all -- 'scripts/hooks/*' '.pre-commit-config.yaml'` returns nothing — **no tracked hook has ever existed**. The MEMORY 2026-04-26 `git grep --cached` reference is **doc-only** (verified: CHANGELOG.md:98 + proposals/005-p09-public-release.md:56/63/76/88 describe a one-off manual sweep, not an installed hook). This is a greenfield build, not a lost-hook restoration. The discrepancy flagged in the steering log is **resolved**.

## Proposal

### Architecture

| Concern | Decision |
|---|---|
| **Install / portability** | Tracked `scripts/hooks/pre-commit` shim symlinked into `.git/hooks/pre-commit` by `init_workspace.install_hook()`. Cloners already run `init_workspace` per CLAUDE.md First-Run Step 2 → portable, **zero new dependency**. Chosen over the `pre-commit` framework (standard, but adds a `pip` dependency + a separate `pre-commit install` step). |
| **Logic location** | `scripts/hooks/sanitisation_guard.py` — importable module (hyphen-free) holding all logic, so it is unit-testable. The hyphenated `scripts/hooks/pre-commit` is a 4-line non-importable shim (git requires the literal filename `pre-commit`). **The shim resolves its own path with `Path(__file__).resolve()` (realpath) (Challenger L6)** so that when git invokes it as the symlink `.git/hooks/pre-commit`, `sys.path` is seeded with the real `scripts/hooks/` dir (where `sanitisation_guard.py` lives) — not `.git/hooks/`. Runtime obs (i)/(ii) invoke *through* `.git/hooks/pre-commit`, proving the import resolves. |
| **Detection scope (L4/L6 — provenance-anchored, declared boundary)** | The guard covers three kinds, each **anchored to provenance in the private ledger** (not a free-text scan): ISIN-shape, exchange-qualified-ticker-shape, and a numeric literal **whose value (in any enumerated representation variant) appears in the gitignored `local/` ledger**. The ledger-provenance *is* the structural anchor (R2-L6) — a value flags only because it is literally in the investor's private corpus. It does **NOT** cover free-text PII (investor name, broker account string, prose theses) or `.env` secrets — both declared out of scope in the module docstring + §Scope so the name `sanitisation_guard` does not over-promise (L4). A general PII/secrets engine is explicitly rejected (Portfolio Manager: no gold-plating). |
| **Install — three explicit cases (Challenger L7)** | `install_hook()` distinguishes: (a) **no hook** → install the symlink; (b) **our own symlink already present** (resolves to the tracked shim) → silent idempotent no-op; (c) **a foreign hook present** → **LOUD operator-visible warning** + print the manual chaining `ln` command + **do not install and do not clobber**. Case (c) never silently leaves the operator believing they are protected. |
| **Scan root (L1 + R2 + R3-L4 — recursive, tracked-set-excluded, drift-proof)** | Extraction reads `local/**/*.md` **recursively**, excluding **every path returned by a single `git ls-files local/` call** (the tracked set). This is drift-proof against a future `.gitignore` change that un-ignores a new subtree (R3-L4): tracked files are re-derived at runtime, not hardcoded. **One** subprocess, not per-file (so none of the R2-L4/L5 per-file fragility returns); on `git` failure it falls back to a static path-exclusion of `local/templates/` — verified today as the only tracked subtree via `git ls-files local/`. The recursive walk is required because the **dominant private corpus lives in gitignored subdirs** (`local/brainstorms/*.md` carries ISINs/NAVs — R2-L1, verified). **`.md` only** (private literals are authored as text); generated `.html` renders are skipped to bound cost — a **documented residual** (R3-L3): a value living *only* in a generated `.html` and never echoed in any `.md` is un-anchored. Named in the module docstring alongside the sub-floor residual. |
| **Block granularity (L9 — per-token)** | The block decision is **per-token**, not per-line: each extracted literal is checked independently. An allowlisted token on a line never whitelists the rest of that line — a real private literal sharing the line still blocks. |
| **False-positive control (the heart)** | Flag only the **intersection** `(literals extracted from the running machine's `local/` ledger) ∩ (staged added lines)`, then apply a **specificity floor**. Double-gated: a token blocks only if it is *both* a private-ledger literal *and* present in the staged diff *and* passes the floor *and* is not allowlisted. |
| **Extraction method** | **Pattern-based, NOT column-index-based** — deliberately avoids the Proposal 025 ghost-contract trap (hardcoded `cols[N]` indices broke silently when the schema shifted). Three kinds: ISIN-format (`[A-Z]{2}[A-Z0-9]{9}[0-9]`), exchange-qualified ticker (`[A-Z]{2,6}\.[A-Z]{1,3}`), specific economic number. |
| **Numeric matching — literal-side variant-enumeration (AMENDMENT, supersedes symmetric normalisation; R4 pivot + redraft-Challenger tightening)** | **The two-sided symmetric normaliser is removed** — R4 confirmed it a spiral (every symmetry fix opened another: date-adjacency, EU-locale). Replaced by a **one-sided** scheme with **no diff-side transform**: (1) extract numeric tokens from the **ledger only**, skipping ISO-date components and applying the floor; (2) for each surviving value, **render the three enumerated representation variants from the ORIGINAL captured token string** (grouping/locale transforms applied to the digit string — **never parse-then-format through `float`/`Decimal`**, which would drop a significant trailing zero `5142.30`→`5142.3` and miss the leak; redraft-L1): plain (`5142.30`), comma-grouped US (`5,142.30`), EU-locale dot/comma (`5.142,30`). **All three variants are rendered for ≥4-digit integers too** (`5100` → `5,100` / `5.100`; redraft-L7), not only for decimal-bearing values; (3) **substring-search the RAW, untransformed staged diff** for any variant, each wrapped as **`(?<!\d) + re.escape(variant) + (?!\d)`** — digit-lookarounds (not `\b`) so the anchor keys on **digit-adjacency** regardless of the variant's terminal char (redraft-L2/L3), and **`re.escape` so the literal `.` is not a regex wildcard** (redraft-L6). A value therefore never matches *inside* a larger number on either end (synthetic illustration: `514` does not fire inside `5142`; `5,142.31` does not fire inside `95,142.31` or `5,142.310`) yet still matches when currency-/pipe-glued (`€5,142.31`, `|5,142.31|` — the non-digit delimiter satisfies the lookaround; these adjacency forms are **caught, not residual** — redraft-L4). Because the diff is searched raw, the date-adjacency + EU-locale **symmetry classes are eliminated at the root**. Failure direction is **fail-CLOSED** (over-enumeration → recoverable false positive via allowlist / `--no-verify`); the EU-variant FP rate on this UK/US-authored corpus is low because the contiguous `N.NNN,NN` form essentially never occurs in UK/US prose (which writes `5.142, 55` with a space; redraft-L5). ISINs + qualified tickers stay **exact-match** (no variants). |
| **Specificity floor (ledger-side only; Amendment 3 — sig-fig decimal floor)** | Applied **only to the ledger-extracted tokens** (one-sided; the diff is searched raw, so no diff-side floor exists to be asymmetric with). A token is "specific" iff: (a) a **decimal with a non-zero fractional part AND ≥3 significant figures** (`63.4`→3✓ qty, `63.41`→4✓ price, `5142.30`→6✓ NAV — but a low-information `1.3`→2✗, `2.6`→2✗ are **dropped**), **or** (b) a **≥4-digit integer** (`5142`, `5100`). The ≥3-sig-fig decimal floor (**Amendment 3**, named constant `_MIN_SIG_FIGS=3`) was added after dogfooding showed a tiny ≤2-sig-fig ledger decimal (a `1.3` ratio) is harvested and its 3-char EU-variant (`1,3`) collides ubiquitously (incl. the guard's own `\d{1,3}` regex). Significant figures: leading zeros not significant, trailing zeros after a decimal point ARE (`63.40`→4✓). ISO-date components are skipped on extraction (one-sided). **Source of numeric literals = the gitignored `local/` ledger ONLY — never `.env`** (R2-L2: `.env.example` is tracked and carries `IBKR_PORT=7497`; `.env` holds secrets/config, not investor economics — out of declared scope). Integer threshold is a named constant (`_MIN_INT_DIGITS=4`, **unchanged** by Amendment 3). ISINs and qualified tickers are exact-match (no floor). **Named residuals (right-sized, see §Scope):** a ≤3-digit private integer (100-share qty, a 3-digit round price) and a ≤2-significant-figure decimal (a `1.3` share price) sit below the floor — low-information, declared, bounded, not silent gaps. |
| **No-op semantics (cloner protection) + misdirection visibility (L11)** | If `local/` does not exist **or** yields zero extractable literals → print a one-line stderr note and `return 0`. Never error, never block a clean commit on a missing `local/`. **When `SANITISATION_LOCAL_DIR` is set to a non-default path** (the test/demo seam), the guard prints *which* dir it is reading from, so a stale exported override from a prior demo is visible rather than silently misdirecting the guard away from the real ledger (Challenger L11). |
| **Block report (PIN 1 — meta-leak)** | Names the **kind + source file + that it appeared in the staged diff**, and the allowlist canonical-hash prefix. **Never quotes the literal value.** |
| **Allowlist (PIN 3/PIN 4)** | `config/sanitisation_allowlist.yml`, loaded via `yaml.safe_load`. Seeds the operator-accepted public identifiers (`isins: [IE000YYE6WK5]`, `tickers: [DFEN.DE]`). A forking cloner inherits and can prune. `canonical_config_hash()` exposed as a named function (parsed-canonical recipe, never raw bytes) and pinned by a golden-hash fixture test. **Self-consistency (R2-L7):** the allowlist file is never a self-leak — its entries are *by definition* allowlisted, so staging the config never self-blocks; no special-case file exemption is needed. **Dual-use caveat (R3-L6, documented):** widening `allow.values` with a number that is *also* a genuinely-private literal silently disables detection of that value — the allowlist is operator-owned and this is intended, but the config carries a one-line comment warning of it. |
| **Emergency bypass** | The block message documents `git commit --no-verify` for genuine false-positive emergencies (this is an anti-mistake guard, not an adversarial control — the maintainer can already bypass). |

### `LOCAL_DIR` override

`sanitisation_guard.py` reads the private dir from `SANITISATION_LOCAL_DIR` (default `<repo>/local`). This serves tests **and** the live runtime-observation demos (point at a synthetic local dir so the BLOCK demo never touches the real ledger). It is a convenience/test seam, not a security boundary — the maintainer can already `--no-verify`.

## Scope & Out-of-Scope

> **Right-sizing the bar (AMENDMENT, per steering 2026-06-04).** S-30 is a **mechanical safety net that catches the leak class manual review keeps missing, and fails *safe* (fail-closed)** — it is **NOT an adversarial-grade perfect redactor**. The R4 loopholes that depended on perfect two-sided symmetry are resolved by *eliminating* symmetry (literal-side variant-enumeration + raw-diff `\b`-search), not by chasing a bulletproof normaliser. Representations the guard does **not** enumerate — space-separated digit groups, scientific notation, values living only in a generated `.html`, and sub-floor (≤3-digit) integers — are a **NAMED, bounded residual** documented in the module docstring and below, not a silent gap. The maintainer's eyes still own that bounded tail; the guard removes the high-frequency, high-magnitude leak (NAVs, costs, ISINs, ≥4-digit and decimal-bearing economics, across plain/US/EU number forms).

**In scope:** the hook, its logic module, the allowlist config, the install wiring, and synthetic-fixture tests. ISIN + qualified-ticker + numeric-value (variant-enumerated) leak classes.

**Out of scope (deferred):** history rewrite of already-public residuals (operator-ruled accept-the-exposure, 2026-06-04 — no action); the `pre-commit` framework path (rejected, see Architecture); **free-text PII** (investor name, broker account string, prose theses) and **`.env` secrets-scanning** — both beyond the three provenance-anchored economic-identity kinds; declared boundaries, not silent gaps (Challenger L4/L6, R2-L2); the **named, bounded numeric residual** — un-enumerated representations (space-separated digit groups, scientific notation), `.html`-only values, sub-floor ≤3-digit integers, and **≤2-significant-figure decimals** (Amendment 3) — documented in the module docstring (fail-closed by design); promoting the "extra-mile / maximise-protection" disposition into the global `/propose` skill (steering log carry-forward — a `~/.claude`-boundary change, not this arc). This proposal touches **only** project files; it stays in the Investments boundary.

## Risks & Mitigations

- **R1 — Test fixture self-leak (PIN 2, loudest).** *Mitigation:* every fixture literal is SYNTHETIC (fake ISIN `XX000...`, fake ticker `FAKE.XX`, fake numbers). A dedicated test asserts the real-ledger values never appear (they are never read by the test). The orchestrator never reads `local/PORTFOLIO.md` into context (PIN 5) — design is from the tracked template only.
- **R2 — Meta-leak in the block message (PIN 1).** *Mitigation:* `find_leaks` returns `(kind, source_file)` tuples only; the value never enters the report. DoD #7 asserts this.
- **R3 — False positives blocking legitimate commits.** *Mitigation:* the intersection + specificity floor + allowlist triple-gate; `--no-verify` documented escape hatch; the floor drops round/common numbers.
- **R4 — Clobbering a foreign pre-commit hook.** *Mitigation:* `install_hook()` only writes when no hook exists; if ours, no-op; if foreign, prints chaining guidance and leaves it untouched.
- **R5 — `git diff --cached` parsing edge cases** (renames, binary files). *Mitigation:* `-U0 --no-color`, scan only `+`-prefixed non-`+++` lines; binary diffs yield no `+` text lines (no false match).
- **R6 — Cross-platform symlink** (Windows). *Mitigation:* project is darwin (verified env); `install_hook` falls back to a printed manual `ln` instruction if symlink creation raises `OSError`. No IRREVERSIBLE step.
- **R7 — Specificity floor fails OPEN on sub-floor 026-class values (the tail risk D named, made concrete).** A floor tuned only against abstract round numbers would silently drop a low-precision private value — a 4-digit NAV (`5142`/`5100`) or a 1-decimal qty (`7.3`) — i.e. pass the very incident class that motivated the guard. *Mitigation:* the floor catches ≥1-decimal values and ≥4-digit non-year integers (the `% 100 == 0` round-shed removed post-Challenger L5), and is **regression-tested against a 026-shape synthetic fixture + independent held-out boundary values** (DoD #6). Steering arbitration 2026-06-04 + Challenger R1 L5.
- **R8 — Scan-root: over-scan vs under-scan (Challenger L1 → R2-L1).** Walking all of `local/` ingests the tracked `local/templates/` examples (R1 over-scan); a non-recursive glob misses the gitignored subdir corpus where most private literals live (R2 under-scan). *Mitigation:* **recursive** `local/**/*.md` **excluding `local/templates/`** — verified the only tracked subtree under `local/` — with no `git check-ignore` subprocess (its fragility, R2-L4/L5, removed at source).
- **R11 — Date-vs-value collision (R2-L3 → R4 pivot).** Harvesting bare years would false-positive on dates. *Mitigation (post-pivot):* date handling is now **one-sided** — ISO-date components are skipped only on ledger extraction; the diff is searched raw with `\b`-anchored variants, so there is no diff-side date transform to be asymmetric with (eliminates R4-L1/L2). A value enumerated and matched against a diff date is at worst a recoverable **fail-closed** false positive.
- **R12 — Numeric matching reliability (R3-L1/L2/L5 → R4 L1/L2/L3, RESOLVED by pivot).** Two-sided symmetric normalisation was a confirmed spiral (R4: 5 structural, up from 2 — each symmetry fix opened another: date-adjacency, EU-locale). *Resolution:* **eliminate symmetry** — literal-side variant-enumeration (plain/US/EU forms of each ledger value) + raw-diff `\b`-search. EU-locale (R4-L3) is now *caught by enumeration*, not missed. Residual is **fail-closed and named** (un-enumerated exotic forms, sub-floor) per §Scope right-sizing. **Runtime obs (v) proves it end-to-end** across all three number forms + the word-boundary FP guard (Verification-is-Runtime-Observation).
- **R9 — Symlink import break disabling the guard (Challenger L6).** If the shim seeds `sys.path` from the un-resolved symlink, the import fails on every commit → operator disables it. *Mitigation:* shim uses `Path(__file__).resolve()`; runtime obs (i)/(ii) prove the import resolves through `.git/hooks/pre-commit`.
- **R10 — Silent under-protection (Challenger L7/L11).** A foreign pre-commit hook, or a stale `SANITISATION_LOCAL_DIR`, could leave the operator believing they are protected when they are not. *Mitigation:* loud warning on a foreign hook (no clobber); print the active dir when the override is non-default.
