## Summary

Close the **S-23** safety item from War Room #3: kill the bare-ticker valuation trap — `reconcile_ibkr.py::_fetch_live_prices:288` calls `yf.Ticker("DFEN")` which resolves to the **US Direxion Daily Aerospace & Defense Bull 3× (USD, ~$68)**, not the held **VanEck Defense UCITS ETF (`DFEN.DE` / ISIN `IE000YYE6WK5`, EUR, ~€55)** — a ~€40 NAV overstatement caught only by IBKR cross-check in #3. The fix makes the **tracked framework** carry portable instrument identity (exchange-qualified ticker + ISIN in the template and ledger) plus a structural code guard, so every public cloner is protected with `yfinance` alone — no IBKR account required.

## The central design tension (resolved, not assumed away)

This is a **public** GitHub repo; `local/PORTFOLIO.md` is **gitignored**. A fresh cloner has **no ledger and no IBKR account** yet must still get correct, non-colliding instrument identity. Therefore the **portable correctness contract cannot live behind IBKR or in the local ledger.**

- **Canonical (portable) path — key-free, stands alone:** the tracked `local/templates/PORTFOLIO.template.md` mandates an **exchange-qualified Ticker** (`DFEN.DE`, not `DFEN`) plus a populated **ISIN** column; the framework price path (`_fetch_live_prices`) keys off the exchange-qualified ticker, so `yf.Ticker("DFEN.DE")` resolves the correct XETRA fund. The bare-symbol collision is made **structurally impossible** by a code guard, not by convention alone. Works for **any** cloner with only `yfinance` — no IBKR, no account, no live ledger required to be correct.
- **Local-authoritative enhancement — deferred to S-21 (`--snapshot`):** IBKR `reqContractDetails().secIdList` ISIN resolution verifies the ledger against the broker and would have flagged the #3 trap. It is **never the sole path** to correct identity, and it is **not in this proposal** — it is the re-scoped S-21 item.

**Canonical for the public repo = the portable path (a).** S-23 (this proposal) builds path (a) only. IBKR enhancement (b) = S-21, split out. (Operator constraint, steering-banked 2026-06-03.)

## 2. ARCHITECT

**Sub-problem 1 — bare-ticker guard + ISIN threading (Confidence 0.9).** Thread `isin` (Holdings col 1) through `_parse_open_holdings` into each position dict. In `_fetch_live_prices`, before the `yf.Ticker` call: normalise `isin = p.get("isin","").strip().upper()` (L5); if `isin` is present, **not** US-prefixed (`not isin.startswith("US")`), and the ticker carries **no exchange suffix** (`"." not in ticker`) → **skip with a loud warning** naming the DFEN→Direxion collision and the fix (qualify the ticker). Precise (keyed to the ISIN country prefix already in the ledger), not an arbitrary allowlist; a legitimate US bare ticker (`US…` ISIN) is unaffected. **(R1-L4 — acknowledged backstop scope:)** the guard is a *fail-safe backstop* to the primary fix (the exchange-qualified-ticker contract in the template + the live-ledger correction); the US carve-out rests on yfinance resolving bare symbols to their US listing by convention (so a `US…`-ISIN bare ticker is the one reliably-correct bare case). It is not a complete venue-resolution solution — that is the qualified-ticker contract's job.

**Sub-problem 2 — partial-mark P&L annotation (Confidence 0.9; R1-L5).** Verified at reconcile_ibkr.py:307-314: the current `_patch_summary` sums unrealised P&L over `p["ticker"] in prices` and renders `€{unrealised:+.2f}` whenever `prices` is non-empty; the `"n/a (yfinance unavailable)"` branch only fires when `prices` is **wholly** empty. So a guard-skip of one holding (e.g. a bare non-US ticker) would silently drop it from the aggregate while rendering as complete. Fix: when `len(prices) < len(positions)`, annotate the P&L string (e.g. `€{unrealised:+.2f} (partial: {len(prices)}/{len(positions)} marks)`) so a missing mark is visible, never hidden. This is the consumer-side complement to the guard — without it the guard's honest skip would re-hide as a silently-wrong aggregate.

**Sub-problem 3 — portable contract (Confidence 0.88).** Add a `## Ticker & ISIN format` note block to the tracked template: Ticker column **must** be exchange-qualified; ISIN column **must** be populated; one-line "why" (bare `DFEN` = US Direxion 3× ≠ held UCITS). This is the canonical key-free correctness contract a fresh cloner inherits.

**Sub-problem 4 — live data fix (Confidence 0.95).** `local/PORTFOLIO.md`: `DFEN` → `DFEN.DE` in the Holdings row (col 0) and the Trade-History row (col 2). **(R2-L18:)** content-anchor on the DFEN rows, not bare line numbers (verified this session at lines 11 + 22, but an untracked mis-patch is `git revert`-irreversible). `_base_symbol("DFEN.DE")=="DFEN"` so IBKR fill-matching (broker emits base symbol `DFEN`) is unregressed.
